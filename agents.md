# inBeTwin — Мультиагентная платформа автоматизации B2B продаж

## Суть проекта

Система автоматизации коммуникаций с клиентами через мессенджеры (Telegram, VK, Pinterest, Facebook), где AI-агенты **автономно** ведут диалоги и выполняют бизнес-операции (создание задач, назначение встреч, квалификация лидов).

**Ключевое отличие:** AI не помощник менеджера, а автономный исполнитель — сам анализирует сообщения, принимает решения, вызывает нужные инструменты.

---

## Проблема

- **63%** B2B компаний не отвечают на входящие сообщения из мессенджеров
- Среднее время ответа **42 часа** вместо критических **5 минут** → потеря 80% лидов
- Менеджер тратит **12 минут** на одно обращение: проверка мессенджеров, поиск информации в 5-7 системах, ручной перенос данных в CRM/Notion/Calendar
- Информация о клиенте фрагментирована (Telegram + VK + Email + CRM) — нет единого контекста

---

## Решение

### Мультиагентная система с оркестрацией

**Supervisor Agent** анализирует входящее сообщение и определяет цепочку выполнения:
1. **Scoring Agent** → оценивает "теплоту" лида (0-100 баллов)
2. **RAG Agent** → ищет релевантный ответ в базе знаний компании
3. **Nurturing Agent** → формирует персонализированный ответ + вызывает инструменты (create_task, schedule_event)

### Tool Calling (автономное выполнение действий)

LLM возвращает структурированные вызовы функций:
```json
// TODO
```

Система **сама** выполняет эти действия через API Notion/Google Calendar без участия человека.

### Цифровые двойники контрагентов

Агрегация данных из всех источников:
- История переписки (последние 50 сообщений из Telegram/VK)
- Поведенческие сигналы (упоминал цену, спрашивал про сроки, быстро отвечает)
- Внешние данные (VK посты, LinkedIn профиль)

→ Формируется единый профиль клиента, который автоматически подставляется в контекст каждого ответа для персонализации.

### RAG-система с гибридным поиском

При вопросе клиента "Какие тарифы?" система:
1. **BM25 поиск** (keyword-based) в PostgreSQL → top-20 результатов
2. **Векторный поиск** (semantic) в Pinecone → top-20 результатов
3. **Объединение** через reciprocal rank fusion → top-3 наиболее релевантных документа
4. LLM генерирует ответ на основе найденных фрагментов

## Архитектура

### Микросервисы (6 сервисов)

1. **Auth Service** (Go) — регистрация, JWT-аутентификация
2. **Social Service** (Go) — интеграция с Telegram/VK, webhook-обработка
3. **Agent Service** (Go) — конфигурация агентов, реестр инструментов
4. **LLM Service** (Go) — обработка сообщений через OpenAI API, tool calling
5. **RAG Service** (Go) — управление базой знаний, гибридный поиск
6. **Lead Scoring Service** (Go) — real-time квалификация лидов

### Базы данных (Polyglot Persistence)

- **PostgreSQL** — основное хранилище (пользователи, сообщения, агенты)
- **Redis** — кэш конфигураций, цифровые двойники (TTL 1 час)
- **Pinecone** — векторная БД для семантического поиска
- **MinIO** — хранение загруженных документов (PDF, Word)

### Коммуникация

- **Синхронная:** REST API через API Gateway (Go Fiber)
- **Асинхронная:** RabbitMQ для событий (message.received, lead.scored)
- **Transactional Outbox:** гарантия доставки критических событий (входящее сообщение, hot lead) через атомарную запись в БД + фоновую публикацию

## Ключевые метрики

**Производительность:**
- Генерация ответа агента: < 10 сек
- Обработка webhook: < 3 сек

**Надёжность:**
- Transactional Outbox для критических событий
- Retry с exponential backoff (3 попытки)
- Circuit breaker при падении микросервиса

**Экономика** (для 100 пользователей):
- Затраты: $470/месяц (OpenAI $300 + Pinecone $70 + хостинг $100)
- Выгода для компании с 10 менеджерами: $12,000/месяц (экономия времени)
- **ROI: 2,350%**, окупаемость за 1 день

## Agile-подход к разработке

**Методология:** Scrum с 2-недельными спринтами

**Спринты:**
- Спринт 1-2: Telegram webhook + базовый ответ через OpenAI API
- Спринт 3-4: Tool calling (create_task, schedule_event)
- Спринт 5-6: RAG-система с гибридным поиском
- Спринт 7-8: Lead scoring
- Спринт 9-10: Мобильное приложение

**Процессы:**
- Еженедельные встречи с научным руководителем (демо + обсуждение блокеров)
- Демонстрация работающего прототипа каждые 2 недели
- Continuous integration: каждый commit → тесты → staging deployment
- Приоритет качеству над скоростью
- Эксперименты для выбора лучших решений (A/B тестирование алгоритмов)

**Управление:**
- GitHub для версионирования
- GitHub Actions для CI/CD
- Notion Kanban для трекинга задач
- Docker Compose для локальной разработки
